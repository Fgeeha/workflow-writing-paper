## 2026-10-31 · v0.2 · ручная проверка сквозного пути на проекте demo-edge

Ввод автора: модель болезней листьев томата на одноплатном компьютере, int8, 1200 фото. Судьи: claude, codex, kev
(правило семейств: автор семейства openai → codex не судит).

**Прогон 1, ideator = gemma4:12b, critic = qwen3.5:9b.** 3 версии (1 + 2 автоправки), 3 мин. Все отклонены:
claude 4.9 / 4.9 / 4.0, codex 4.5 / 4.9 / 5.1. Причина содержательная — ideator выдумывает факты, которых автор
не давал (transfer learning, «70 %», результаты сравнения архитектур). Судьи это ловят, автоправки не помогают.
Вывод: gemma4:12b — хороший критик, но не ideator. Найдены два дефекта системы: судьям не передавался исходный
ввод автора («1200 не подтверждено материалами»); checker требовал точное слово «Журналы» при заголовке
«Типы журналов и конференций». Исправлено: `source` в артефакте, разделы по основам слов.

**Прогон 2, ideator = codex, critic = gemma4:12b.** 2 версии, 3 мин. v4: claude 8.2 accept, checker — 6 блокеров
(codex написал без заголовков разделов); после автоправки v5: checker чист, claude 8.2, kev — ошибка HTTP 413.
Причина: `json.dumps` экранировал кириллицу в `\uXXXX`, 22 KB текста → 65 KB > лимит 64 KiB. Исправлено
(`ensure_ascii=False`); заодно отказавший судья теперь заменяется следующим подходящим.

**Перепроверка v5:** claude 8.2, kev 6.98 при пороге 7.0, блокеров нет → система остановилась, решение за автором.
Принято через override с причиной (сжатая шкала kev). Поведение правильное: граница стадии — точка остановки.

Выводы по v0.2:
- Сквозной путь работает на реальных моделях; каждая версия, проверка и решение лежат файлами в проекте.
- Decision-модель kev как второй судья — на границе порога по любому тексту (6.9–8.1); до калибровки шкалы
  ставить kev третьим, а не вторым, иначе override потребуется почти всегда.
- Правило семейств сужает выбор: при ideator = codex доступны claude и локальные; при ideator = claude —
  codex и локальные. Для двух сильных судей нужен ideator из локального семейства или третья подписка.

**Раздел «Эксперимент», section_writer = codex, судьи claude + kev.** 3 версии, ~4 мин. Числа из реестра
(0,94 ← 0,937 по округлению профиля; 86,40; 11,20) checker принял; число 240 из поля `note` реестра —
отклонил во всех версиях, где оно появлялось. Claude 5.7–6.3, kev 6.3–6.5 → major; артефакт ждёт автора.
Текст честный: codex прямо пишет, чего в данных нет, и ставит {pending}. Оценки низкие по существу —
в демо-проекте три числа и нет плана экспериментов.

Найденное противоречие правил: checker считает источником только `value`, судья claude требовал взять 240 из
`note`. Закрыто: судьям и писателю явно сказано, что `note` — пояснение, не источник чисел.
Решение по судьям: kev переставлен после gpt-oss — при сжатой шкале (6.3–7.0 на всём) он как второй судья
почти всегда роняет `min_overall` ниже порога.

Критерий готовности v0.2 выполнен: сквозной сценарий проходит в тесте на fake и вручную на реальных моделях;
каждая версия, отчёт судьи и решение автора — файлы в каталоге проекта.
